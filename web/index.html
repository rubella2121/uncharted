How the verdict is decided
NOT SAFE
Any test case that passed in the baseline fails in the candidate. A regression always wins, even if other data is missing.
INCONCLUSIVE
Some cases timed out or errored, so they could not be verified. Missing data never counts as a pass.
RISKY
No regressions, but p95 latency rose more than 25% or total cost more than 30%.
SAFE
No regressions, every case verified, latency and cost within limits.

How MongoDB is used

  • Stable IDs. Result _id = hash(run_id, test_case_id); a unique index on {run_id, test_case_id} makes re-ingestion safe.
  • Schema validation. A strict envelope (run_id, status, passed, timestamp…); output and checks stay flexible.
  • Aggregation. $group + $switch classifies each test case; $percentile computes p95 latency.
  • Change streams: this page updates as MongoDB writes results.
  • Indexes. Results by run, latest results per version, recent runs, runs by commit.
  • History. Every run and verdict is stored, so any two runs can be compared later.
